# Flutter Frontend
In this folder are all the [Flutter](https://docs.flutter.dev/) related files.
This folder is essentially the app and what the user sees. 
It has a dependency to the backend which ensures that there is data consistency.
You will be doing most of your work in this folder.

## Getting Started
Before you can run the app, you will need to add the Firebase options file to this project.
To do this, follow these steps:
1. Complete the [backend tutorial](../backend/README.md) to create a Firebase project which satisfies the requirements
2. Watch this [tutorial to setup Firebase for Flutter](https://youtu.be/Wa0rdbb53I8?list=PL4cUxeGkcC9j--TKIdkb3ISfRbJeJYQwC)
Once you have completed this appropriately, you can start to work with the project.

### Toolchain requirements (Android)
The Android build was updated to the minimum versions required by current Flutter releases:

| Tool | Version |
|---|---|
| Flutter | 3.47 (stable) |
| Gradle | 8.14.3 |
| Android Gradle Plugin | 8.11.1 |
| Kotlin | 2.2.20 |
| JDK | 17 or 21 |
| Android NDK | 27.0.12077973 |

Gradle 8.x cannot run on the JDK 25 bundled with recent Android Studio versions. If the build fails with `Unsupported class file major version 69`, point Flutter to a JDK 17 or 21 installation:
`flutter config --jdk-dir="<path to JDK 21>"`

On recent Android emulator images (API 36+) the screen may stay black with the Impeller renderer. Run the app with `flutter run --no-enable-impeller` in that case; physical devices are not affected.

### Running the tests
- Unit and widget tests: `flutter test`
- Integration test of the "publish an article" journey: start the Firebase emulators from `backend/` (`firebase emulators:start --only firestore,storage`), then, with an Android emulator running, `flutter test integration_test`. The journey runs against the emulators with the real security rules, so no test data reaches the Firebase project.

### Generate files for routing, di etc.:
`dart run build_runner build --delete-conflicting-outputs`

Only the local database (`app_database.g.dart`, floor_generator 1.5) is generated (see `build.yaml`). The news API client (`news_api_service.g.dart`) was generated by `retrofit_generator` 3, which does not run with Dart 3 and blocked newer generators, so it was removed and the generated client is kept as committed.
### Generate the icons:
`flutter_launcher_icons` is not part of this project's dependencies, so the app uses the default Flutter launcher icon.
### Install the Project Dependencies (in pubsec.yaml)
`flutter pub get`
