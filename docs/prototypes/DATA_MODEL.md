# Prototype 1 – Data model of the app

This diagram shows every place where the app keeps articles and how they relate. The written schema, with its validation rules, is in [backend/docs/DB_SCHEMA.md](../../backend/docs/DB_SCHEMA.md).

GitHub renders the diagrams below. In other viewers, paste them into [mermaid.live](https://mermaid.live).

## Entities and relations

```mermaid
erDiagram
    FIRESTORE_ARTICLE ||--|| STORAGE_THUMBNAIL : "thumbnailURL points to"
    FIRESTORE_ARTICLE }o..o{ LOCAL_SAVED_ARTICLE : "can be saved as"
    NEWS_API_ARTICLE }o..o{ LOCAL_SAVED_ARTICLE : "can be saved as"

    FIRESTORE_ARTICLE {
        string articleId PK "generated by Firestore"
        string title "1 to 100 characters"
        string content "1 to 5000 characters, Markdown"
        string thumbnailURL "media/articles/articleId.ext"
        timestamp publishedAt "server time"
    }
    STORAGE_THUMBNAIL {
        string path PK "media/articles/articleId.ext"
        string contentType "image/jpeg, image/png or image/webp"
        int size "at most 5 MB"
    }
    NEWS_API_ARTICLE {
        string author
        string title
        string description
        string url
        string urlToImage
        string publishedAt
        string content
    }
    LOCAL_SAVED_ARTICLE {
        int id PK "SQLite table article"
        string author
        string title
        string description
        string url
        string urlToImage
        string publishedAt
        string content
    }
```

- **Firestore `articles`** holds the articles written by journalists. Each document has exactly four fields; the security rules reject any other shape.
- **Cloud Storage `media/articles`** holds one thumbnail per article. The file and the document share the same `articleId`, so each document points to exactly one file.
- **NewsAPI** articles are not stored by the app: they are read on every feed refresh.
- **Local SQLite table `article`** keeps the articles the reader saves, from either source, so they can be read offline.

## How the feed is built

```mermaid
flowchart LR
    NewsAPI[(NewsAPI)] -->|top headlines| Feed
    Firestore[(Firestore<br/>articles)] -->|50 newest| Feed
    Storage[(Cloud Storage<br/>media/articles)] -->|thumbnail download URL| Feed
    Feed[Combined feed<br/>newest first] -->|save| SQLite[(Local SQLite<br/>article)]
    Publish[Publish screen] -->|1. upload thumbnail| Storage
    Publish -->|2. create document| Firestore
```

The thumbnail is uploaded before the document is created, so a document never points to an image that does not exist yet.
