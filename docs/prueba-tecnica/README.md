# Prueba Técnica — Documentación de Orientación

Conjunto de documentos en español que organizan el abordaje de la prueba técnica **Applicant Showcase App** de Symmetry. Pensados para leerse **en este orden**:

| # | Documento | Para qué sirve |
|---|---|---|
| 0 | [00_RESUMEN.md](./00_RESUMEN.md) | Qué pide la prueba, en una sola página. Entregables, restricciones y criterios de evaluación. |
| 1 | [01_PLAN_FASES.md](./01_PLAN_FASES.md) | Plan **integrado** (Fases 0–9) que incluye los requisitos oficiales + todas las mejoras 🔴🟡 del análisis + overdelivery #15 (router declarativo) y #21 (design tokens). Listo para ejecutar. |
| 2 | [02_CHECKLIST.md](./02_CHECKLIST.md) | Checklist granular por área (entorno, backend, domain, presentation, data, calidad, seguridad, entrega). |
| 3 | [03_ANALISIS_ARQUITECTURA.md](./03_ANALISIS_ARQUITECTURA.md) | Diagnóstico del código actual y propuestas de mejora priorizadas. |

## Cómo usar esta documentación

1. **Antes de escribir código:** leer `00_RESUMEN.md` para alinear expectativas.
2. **Al planificar el día:** usar `01_PLAN_FASES.md` como cronograma.
3. **Durante cada fase:** marcar avance en `02_CHECKLIST.md`.
4. **Al refactorizar o proponer overdelivery:** apoyarse en `03_ANALISIS_ARQUITECTURA.md`.
